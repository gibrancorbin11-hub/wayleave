FROM INSTALL TO FIRST REQUEST

Start with visibility.

No wallet or payment rules needed.

  1. Install the middleware.Add Wayleave to your existing Express app.
  2. Create a Meter account and issue a key.Keep the key in a server environment variable.
  3. Send a request. Open your ledger.Your existing application keeps handling the response.
Create your account →

Signing in does not start a subscription. Hosted Meter terms are below.

app.js · existing Express app
import Wayleave from 'wayleave';

if (!process.env.WAYLEAVE_METER_KEY) {
  throw new Error('Set WAYLEAVE_METER_KEY');
}

const gate = new Wayleave({
  meter: {
    apiKey: process.env.WAYLEAVE_METER_KEY,
  },
});

// Mount before the routes you want to observe.
app.use(gate.express());

No prices, blocking rules or rate limits configured. Add them when you’re ready.

ONE CALL, ANY LANGUAGE

Ask who is calling.

Send a request’s signature headers. Get back who signed it, whether that key is in the registry, and which lane it belongs in.

  1. No install.Python, Go, Ruby, a Worker, a shell script. The middleware’s ceiling is its runtime; this removes it.
  2. Same verifier as the middleware.The endpoint calls the code the package ships. A parity test fails the build if the two ever disagree.
  3. If we are down, allow the request.You get a 503 and decide. Never block your traffic on our availability — that is what the in-process middleware is for.
Get a key →

The reasons array is the point. A yes or no is a commodity; why a request landed in a lane is what you paste into a log.

any terminal
curl -sX POST https://api.wayleave.dev/v1/identify \
  -H 'authorization: Bearer wl_live_...' \
  -H 'content-type: application/json' \
  -d '{
    "method": "GET",
    "url": "https://example.com/api/data",
    "headers": {
      "signature":       "sig1=:...:",
      "signature-input": "sig1=(\"@method\" \"@authority\");keyid=\"...\";alg=\"ed25519\"",
      "signature-agent": "\"https://agents.example.com/.well-known/...\""
    }
  }'

{
  "lane": "verified_agent",
  "verified": true,
  "identity": { "operator": "Example Research" },
  "reasons": []
}

Verification is cryptographic. A caller cannot assert an identity — only the signature decides.
